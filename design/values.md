# 値と共有

[設計ノートの入口](README.md)

## 現在

名前はオブジェクトを指す。`let b := a;`は共有、`let b = a;`と`copy(a)`は型別のコピーである。宣言後の`a = b`は外側の同一性を保って中身を更新し、`a := b`は名前の共有先を変更する。整数も同じ規則を使う。

配列・フィールド・タプル・enumのpayload・捕捉環境への格納は共有を基本とする。既定のコピーは各子の`__copy__`を呼び、利用者向けの`copy`も`__copy__`へ接続する。手動コピーが共有を返す場合はその共有を解析する。集約値への`=`は外側だけを保ち、子をコピーで置き換えるため、以前取得した子への共有は古い値を保持する。

`let x = value;`はコピーによる初期化として使える。`let x: Int;`のように初期値なしで宣言した後は、最初に`x := value;`が必要である。未初期化の`x = value;`は更新する対象がないため使えない。

`fixed`は名前の結び直し、`readonly`は共有経路からの変更、`noescape`は引数の共有の持ち出しを制限する。省略時はrebindable・mutable・escapeである。readonlyは別名・要素・フィールド・戻り値へ伝播するが、別の更新可能な経路からの変更を禁止するものではない。独立した値を返すコピーでは更新可能な値を作れる。手動コピーが共有を返す場合はreadonlyを引き継ぐ。

評価は左から右に一度ずつ行い、オブジェクトを保持する。後続の式が同じ実体を更新すれば、先に保持した値からも更新が見える。名前の結び直しは保持済みの共有先を変更しない。短絡する右辺は必要な場合だけ評価する。

スコープが終わっても、他から共有されるオブジェクトは生存する。文末・条件の終了・ジャンプで不要な一時共有を解放し、文字の共有などが不必要に構造変更を妨げないようにする。詳細は[現行の意味規則](../docs/reference/semantics.md)にある。

## 今後の方針

`readonly T`と`Vec<readonly T>`で外側のコンテナと格納要素の更新権限を区別する。外側を新しく作り、readonlyな要素を共有して集めた配列では、外側の並べ替え・削除を許しながら要素の更新を禁止できる規則とする。

同じ外側のコンテナを共有したまま、更新可能な要素型をreadonlyな要素型へ変える変換は許さない規則とする。readonlyな要素を挿入されると、元の経路が持つ更新権限の保証を壊すためである。

### β11で採用する循環共有とコピーの方針

再帰型に伴う循環共有を認め、循環を切る責任は利用者が持つ。参照カウントを基本とし、GCや循環回収器はβ11の実装前提にしない。外側の名前を手放すだけでは内部の循環は切れず、切り忘れた循環はリークする。フィールドの共有先の結び直し、コンテナのclearや要素削除など、通常のRusk操作で内部の辺を切れるようにする。残る共有元がある値は生存し、最後の共有がなくなれば回収される。

自動生成する`__copy__`は、各フィールドの`__copy__`を使う単純な再帰コピーとする。Vecも各要素を個別にコピーし、元の内部共有を再現しない。コピー先の対応表や循環を保つ複製は自動生成の責務に含めず、必要な場合は利用者が`__copy__`を定義する。自動コピーには循環する値のコピーを完了させる保証を設けない。

手動の`__copy__`を優先し、子の共有や入力そのものの返却も認める。共有先と効果は通常の関数と同じ規則で解析し、関数名だけで独立性やreadonlyの解除を仮定しない。`copy(a)`とコピー初期化は`__copy__`を使い、既存の値への代入は外側の同一性を保つ`__assign__`が必要なコピーを呼ぶ。

これらの基盤はβ11で実装した。完成条件と残る論点は[β11の作業計画](../docs/development/plan.md)にある。

## 未決定

`readonly T`の型表記を既存の変数・引数注釈と共有経路の解析へ接続した。型引数は不変であり、根元の権限を基の型へ接続しても解析上の制限は残る。[現在の仕様](../docs/reference/access.md#readonly-types)を参照する。

未知の外部操作を含む保持・変更の解析精度、共有の同一性を直接調べる公開操作、一時値への代入の最終的な制限は保留する。[型](types.md)と[構文](syntax.md)も参照する。
